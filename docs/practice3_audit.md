# Проверка практической работы № 3

Дата проверки: 27 октября 2026 года. Тема: **система бронирования фотостудии FocusFrames**.

Проверен проект `UP3/UP2/library_web`, требования документа «Практика 3 — валидация и связи», приложения Б и раздела 2 приложения А. Название каталога `library_web` историческое: приложение, модели и данные относятся к фотостудии.

## Соответствие методичке после исправлений

| Требование | Реализация |
|---|---|
| Продолжение ПР2, пять сущностей | Бронирование, зал, фотограф, клиент, оборудование |
| Сохранение между запусками | Все пять коллекций в `shared_preferences`, JSON, ожидание записи при изменениях |
| `toJson` / `fromJson`, отсутствующие и null-поля | Все пять моделей, запасные значения и безопасный разбор дат и списков |
| Создание и редактирование | Один экран формы на сущность, режим определяется ID |
| Валидация каждого поля | Общие валидаторы `core/validators.dart`, ограничения и проверки связей |
| Ошибки под полями | `EntityForm`, включая ошибки уникальности и связей из репозитория |
| Полный CRUD | Списки, отдельные карточки просмотра, создание, изменение, удаление |
| Многие к одному | Зал и клиент в форме бронирования; зал в форме оборудования; выбор ID через dropdown |

| Защита удаления связанных записей | Зал, клиент и фотограф; сообщение с числом зависимостей; общие правила для одиночного и массового удаления |

| Логическое / физическое удаление, восстановление | Для всех пяти сущностей; восстановление повторно проверяет уникальность |

## Найденные и исправленные недочёты

1. Множественный выбор изменял локальный список без `FormField.didChange`, поэтому `validate()` видел прежнее значение. Исправлены выбор и программный сброс при каскаде.
2. Ошибка уникальности оставалась после изменения поля и блокировала повторную отправку. Теперь она относится к отклонённому значению и снимается после исправления.
3. Флаг несохранённых изменений менялся без перестроения PopScope. «Отмена» сбрасывала его, а переходы `context.go` обходили защиту. Подключена проверка выхода маршрута и общий диалог.
4. Уведомление о миграции читалось до создания репозиториев, а ScaffoldMessenger искался выше нужного контекста. Репозитории инициализируются до чтения уведомления, используется ключ messenger.
5. Обратные ссылки бронирования менялись в памяти без записи связанных коллекций. Теперь сохраняются и восстанавливаются при запуске; ссылки оборудования также согласуются с `hallId`.
6. Массовое удаление обходило проверки связанных записей. Проверка перенесена в репозитории и выполняется до изменения всего набора. Физическое удаление учитывает зависимости из корзины, чтобы восстановление не создавало потерянные ссылки.
7. Не было самостоятельных карточек просмотра. Добавлены маршруты `/<сущность>/:id` и кнопки просмотра во всех списках.
8. Некорректная дата вроде `2026-02-30` нормализовалась DateTime и считалась допустимой. Проверяется точный формат и реальный календарный день. Необязательный срок абонемента допускает пустое значение.
9. Несуществующий ID редактирования открывал пустую форму создания. Теперь выводится «Запись не найдена».
10. Справочники ограничивались первой сотней записей, после изменения клиентов могли оставаться устаревшими. Теперь загружается весь активный справочник и обновляется после операций.
11. Указатель сортировки DataTable не учитывал колонку чекбокса; для скрытой колонки мог передавать `-1`. Индекс исправлен, неизвестные значения фильтров больше не вызывают исключение dropdown.
12. Поля фильтров не отражали сброс параметров в URL. Общий `QueryTextField` синхронизирует текст и сохраняет фокус при наборе.
13. Демонстрационные брони содержали несовместимые связи фотографов и превышение вместимости. Начальный набор приведён к согласованному состоянию. Уже сохранённые пользовательские записи автоматически не заменяются демонстрационными.

## Проверка

Команды из корня проекта:

```powershell
flutter analyze
flutter test --timeout 60s
flutter build web
```

Результат проверки: **54 теста пройдены**, `flutter analyze` — **No issues found**, `flutter build web` — **успешно**. Проверено открытие 30 маршрутов списков, форм и карточек, включая отсутствующие записи.

Дополнительные проверки находятся в `test/practice3_regression_test.dart`: календарные даты, все модели, целостность начального набора, массовое удаление, зависимости корзины, сохранение обратных ссылок, перенос оборудования, восстановление дубликата, множественный выбор, исправление ошибки уникальности, диалог выхода, миграция и открытие маршрутов всех пяти сущностей.

Сохранение в тестах проверяется повторным созданием репозиториев поверх того же хранилища. Это автоматическая проверка сериализации и восстановления; для отчёта требуется также демонстрация обновления вкладки браузера.

## Материалы для сдачи

Схемы, словарь данных и ограничения полей: [domain_model.md](domain_model.md).

Методичка отдельно требует ссылку на репозиторий и снимки экранов. Публикация репозитория в ходе проверки не выполнялась. Для снимков используйте:

1. `/bookings/new`: выбор клиента и зала, несколько фотографов.
2. Попытка отправить незаполненную форму: несколько ошибок одновременно.
3. Код существующей брони, например `BR-2026-0001`: ошибка под полем кода.
4. Удаление используемого зала: сообщение с количеством связанных записей.
5. `/clients/new`: вложенная группа «Абонемент» — аналог связи 1:1.
6. Изменить запись и сохранить, сделать снимок, обновить вкладку и сделать второй снимок той же записи.

Для сохранения между запусками используйте один origin (одни и те же протокол, адрес и порт):

```powershell
flutter run -d chrome --web-port=5555
```

В ПР3 хранилище локальное, отдельный сервер и SQL-база не используются. Проверка календарных пересечений по времени, оплата и роли относятся к дальнейшему развитию и не заявлены как реализованные возможности этой работы.

При подготовке отчёта дополнительно исправлено исчезновение полей в форме с множественным выбором: отложенная разметка теперь получает копию списка FieldSpec. Проверено наличие всех полей формы бронирования; уточнены отступы и переносы полей.
