# Права пользователей фотостудии

Клиент самостоятельно оформляет запись на съёмку, менеджер работает с
бронированиями и клиентами, администратор управляет настройками студии и
пользователями. Изменение правил применяется в интерфейсе, маршрутах и API.

| Операция | Клиент | Менеджер | Администратор |
|---|---|---|---|
| Просмотр залов, фотографов и оборудования | Да | Да | Да |
| Создание брони | Только для себя | Для выбранного клиента | Для выбранного клиента |
| Продление своей брони в личном кабинете | Да | Нет | Нет |
| Изменение, отмена и завершение бронирований | Нет | Да | Да |
| Создание и изменение клиентов | Нет | Да | Да |
| Изменение залов, фотографов и оборудования | Нет | Нет | Да |
| Логическое удаление клиентов и броней | Нет | Да, если нет запрещающих связей | Да, если нет запрещающих связей |
| Логическое удаление справочников | Нет | Нет | Да, если нет запрещающих связей |
| Физическое удаление и восстановление | Нет | Нет | Да, с проверкой связей |
| Пользователи, роли и статистика | Нет | Нет | Да |

Роль фотографа сохранена: просмотр каталога, без создания бронирований и
управления данными.

## Клиентское бронирование

В личном кабинете и на главной есть кнопка «Забронировать зал». В списке
залов также есть кнопка бронирования конкретного зала: форма сразу выбирает
этот зал. Клиент указывает дату, фотографов, длительность, участников,
тип съёмки и контактную почту.

В форме нет выбора другого клиента и ручного кода. Сервер определяет
владельца по токену и профилю пользователя, генерирует уникальный код и
назначает статус «Активно». Попытка передать чужой clientId получает 403.
Занятый зал или фотограф даёт 409; неверные данные или прошедшая дата — 422.
После сохранения открывается список собственных бронирований.

## Проверка прав

Открытие менеджером `/halls/new`, `/photographers/1/edit` или
`/equipment/new` приводит на экран отказа. Прямой запрос изменения этих
справочников также получает 403. Изменение localStorage не даёт серверных
прав: сервер использует подписанный токен и собственную запись пользователя.

Проверки: `flutter test` и `node server/test-booking-roles.js`.
Тест формы подтверждает скрытие чужого профиля и кода, подстановку своей
почты, выбор зала и переход к собственным записям после сохранения.
API-тест проверяет создание брони клиентом, запрет подмены владельца,
422/409 и отдельные полномочия менеджера и администратора.
